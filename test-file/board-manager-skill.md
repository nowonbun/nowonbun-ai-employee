# 게시판 개발 관리 스킬

## 적용 범위
- 게시판 개발 업무를 맡은 관리 AI의 계획, 위임, 통합 판단에 적용합니다. 작업 AI의 구현 절차나 면담에는 적용하지 않습니다.
- common-work-skill의 공통 처리 절차를 전제로 하며 여기서는 게시판 개발의 작업 분해와 검수만 정의합니다.
- 기능과 기한은 현재 업무 지시, 기술 선택은 승인된 프로젝트 결정, 인터페이스는 합의된 계약을 기준으로 합니다. 아래 점검 항목은 기능 추가 승인이 아닙니다.

## Must

### 요구사항과 계약
- 기능을 필수 범위, 제외 범위, 결정 대기로 구분합니다. 목록·상세·작성·수정·삭제 중 필요한 기능과 인증 방식, 작성자 권한, 검색·페이지 처리 여부를 확인합니다.
- 저장소의 기존 구조와 실행·시험 방법을 먼저 확인합니다. 신규 프로젝트이면 기술 스택, 작업 루트와 실행 환경을 사용자에게 확인한 뒤 구현을 위임합니다.
- API를 사용하는 경우 메서드, 경로, 요청·응답 필드, 오류 형식, 상태 코드와 페이지 처리 방식을 백엔드·프런트엔드가 공유할 계약으로 정리합니다. 서버 렌더링이면 화면 경로와 폼 계약으로 대체합니다.
- 인증이 범위에 포함되면 익명·작성자·타인의 허용 동작을 표로 정리합니다. 관리자 권한은 요청된 경우에만 추가합니다.

### 분배와 의존성
- 기본 담당 경계는 백엔드의 데이터·서버 처리, 프런트엔드의 화면·사용자 상호작용, QA의 시험·결함 재현으로 나눕니다. 실제 직원의 담당 업무와 권한에 맞게 조정합니다.
- 각 작업에 수정 허용 경로, 입력 계약, 산출물, 검증 명령 또는 시나리오와 완료 조건을 포함합니다. 공유 파일의 변경 담당자는 한 번에 한 명으로 정합니다.
- 계약 확정 후 서버와 화면 작업은 서로 다른 파일에서 진행할 수 있습니다. 모의 API를 사용하면 계약 버전과 모의 실행임을 명시하고 실제 통합 검증을 별도 작업으로 남깁니다.
- QA에는 구현 전에 요구사항과 계약을 전달해 시험 설계를 맡길 수 있습니다. 실행 시험은 대상 구현과 테스트 환경이 준비된 뒤 진행합니다.
- 공유 계약 변경이 필요하면 영향받는 담당자와 후속 검증을 식별하여 순서를 다시 조정합니다. 동시 수정 충돌은 해당 파일 작업만 멈추고 해결합니다.

### 검수와 보완
- 완료 조건은 관찰 가능한 동작으로 작성합니다. 예를 들어 작성 성공 뒤 상세·목록에 반영되는지, 잘못된 입력이 거부되는지, 합의된 권한 제한이 서버에서 적용되는지 확인하도록 합니다.
- QA 결함은 데이터 손실·권한 우회, 필수 흐름 중단, 우회 가능한 표시 문제로 구별하고 앞의 두 범주는 해결 전 완료 판단을 보류합니다.
- 결과 보고 전 동일한 통합 대상에서 계약 적합성, 필수 시나리오, 회귀 검사와 실행 안내를 대조합니다. 작업별 성공만으로 통합 성공을 선언하지 않습니다.
- 실패 보완은 원인과 담당 범위가 확인된 별도 작업으로 한정합니다. 환경 부족은 코드 결함과 구별하고 재시험 조건을 명시합니다.

## Must NOT
- 댓글, 첨부, 알림, 관리자 화면이나 외부 배포를 요청 없이 범위에 넣지 않습니다.
- QA 통과를 만들기 위해 완료 조건을 낮추거나 미실행 검사를 성공으로 집계하지 않습니다.
- 담당자의 변경을 확인하지 않고 공유 파일을 덮어쓰거나 구현 작업을 중복 배정하지 않습니다.

## Definition of Done
- 요구사항과 계약에서 담당 작업, 산출물, 통합 시험 결과까지 연결됩니다.
- 필수 조건 미충족과 사용자 결정 대기가 최종 판단에 반영됩니다.
- 실행 방법과 알려진 제한을 포함한 사용자 보고가 준비됩니다.
