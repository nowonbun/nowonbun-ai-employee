# 게시판 개발 테스트 팀 구성안

이 문서는 등록할 때 사용할 제안입니다. 파일 작성만으로 직원, 조직, 스킬이나 정책이 시스템에 등록되지는 않습니다.

| 게시판 백엔드 개발자 | 작업 AI | 게시글 데이터, 서버 처리, 입력 검증과 서버 권한 검사 | board-development-worker | board-backend-persona.md |

- 조직 이름 제안: 게시판 개발 팀. 관리 AI를 상위에, 작업 AI 3명을 직속으로 배치합니다.
- 전체 AI 정책에는 기존 common-work-skill을 적용합니다. 게시판 전용 스킬 2개는 공통 정책이 아니라 해당 직원의 개별 스킬로 연결합니다.
- 작업 AI 3명은 같은 작업 스킬을 사용하되 서로 다른 담당 업무와 페르소나로 전문 영역을 구분합니다.
- 관리 AI에서 작업 AI 3명으로 각각 호출 권한을 설정합니다. 조직도상 직속 관계만으로 호출 권한을 대신하지 않습니다.

## 등록 순서

1. 스킬 화면에 common-skill.md, board-manager-skill.md, board-worker-skill.md의 전체 본문을 각각 등록합니다. 기존에 같은 스킬이 있다면 중복 생성 대신 현재 등록 내용을 확인합니다.
2. AI 정책에 공통 스킬을 연결합니다. 기존 정책이 있다면 필요한 기존 항목을 보존하고 적용 대상을 확인합니다.
3. 페르소나 템플릿 화면에서 각 파일 제목을 템플릿 이름으로, 파일 전체 본문을 역할·행동 지침으로 등록합니다. 페르소나는 스킬 파일이 아니므로 스킬로 등록하지 않습니다.
4. 직원 생성 시 표의 역할·담당 업무·개별 스킬·페르소나를 선택합니다. 모델과 실제 존재하는 작업 위치는 테스트 환경에 맞게 지정합니다.
5. 조직 배치와 호출 권한을 설정하고 직원의 초기 실행·현재 세션 상태를 확인합니다.
6. 작업 루트, 기술 스택과 제품 요구사항을 확정한 업무 지시를 관리 AI에게 전달합니다. 등록 후 기존 세션의 페르소나가 자동 변경된다고 가정하지 말고 실제 세션 설정을 확인합니다.

## 작업 폴더 경계 제안

- 관리 AI가 프로젝트 구조를 확인하여 실제 경로로 구체화합니다. 현재 AI 직원 시스템의 src 자체를 게시판 개발 대상으로 간주하지 않습니다.
- 신규 게시판은 허용된 워크스페이스 안의 별도 프로젝트 경로를 명시합니다. 기존 프로젝트이면 사용자가 지정한 저장소를 사용합니다.
- 서버·화면·시험 경로의 수정 소유자를 나누고 공용 계약, 패키지 설정과 잠금 파일은 한 담당자가 순차 수정하도록 합니다.
- 모든 AI가 같은 OS와 파일을 사용할 수 있으므로 담당 경계만으로 파일 접근이 격리되었다고 가정하지 않습니다.

## 테스트 조직 관찰 기준

- 계약이 준비되기 전에 양쪽 구현이 서로 다른 필드로 진행되지 않는가?
- 중복 요청이나 중단 후 재개에서 같은 작업·산출물이 중복 생성되지 않는가?
- 타인 수정·삭제 금지 요구가 있으면 서버 검증과 거부 시험이 있는가?
- 모의 API 성공과 실제 통합 성공이 구분되는가?
- QA가 제품 코드를 임의로 고치지 않고 결함을 보고하는가?
- 실패·미실행 시험이 최종 보고에 남는가?

위 항목은 향후 행동 테스트의 관찰 기준이며, 이번 문서 작성에서 AI 직원의 실제 실행을 검증한 결과는 아닙니다.
