# 게시판 개발 작업 스킬

## 적용 범위
- 게시판 개발 작업을 배정받은 작업 AI에 적용합니다. 아래 분기 중 시스템의 담당 업무와 현재 작업에 해당하는 부분만 사용합니다.
- 관리 AI의 업무 분배나 면담에는 적용하지 않습니다. 공통 기록·제출·재시도 절차는 common-work-skill을 따릅니다.

## Must

### 구현·검증 전 확인
- 작업 목표와 허용 경로, API 또는 화면 계약, 기존 코드 관례와 실행 방법을 확인합니다. 예상과 다른 사전 변경은 보존하고 충돌 여부를 보고합니다.
- 계약이 없거나 서로 다른 계약을 받았다면 영향을 받는 구현을 멈추고 관리 AI에게 결정을 요청합니다. 담당 범위 안의 되돌릴 수 있는 조사와 시험 설계는 진행할 수 있습니다.
- 새 의존성, 데이터 스키마 또는 공유 계약 변경이 필요하면 필요성과 영향 범위를 제안합니다. 승인된 작업 범위 안의 변경만 실행합니다.

### 백엔드 담당
- 합의된 게시글 필드와 제약을 저장 구조와 서버 입력 검증에 반영합니다. 빈 제목, 길이 제한과 존재하지 않는 게시글의 응답을 시험합니다.
- DB 조회는 파라미터 바인딩이나 동등한 안전한 접근 방식을 사용합니다. 목록의 정렬 기준과 페이지 경계가 재현 가능하도록 구현합니다.
- 인증·작성자 제한이 요구되면 서버에서 신원을 확인하고 읽기·변경 권한을 각각 검증합니다. 클라이언트가 보낸 작성자 ID만 신뢰하지 않습니다.
- 스키마 변경은 테스트 DB에서 적용·복구 방법을 검증하고 기존 데이터에 미치는 영향을 기록합니다.
- API 또는 서버 동작 시험, 샘플 요청·응답과 화면 담당자가 사용할 연결 방법을 전달합니다.

### 프런트엔드 담당
- 합의된 화면 흐름을 구현하고 로딩, 빈 목록, 요청 실패, 입력 오류와 존재하지 않는 게시글 상태를 구분해 표시합니다.
- 계약에 맞춰 실제 응답을 처리하고 사용자가 입력한 내용은 기본적으로 텍스트로 표시합니다. 리치 텍스트가 범위에 있으면 승인된 정화 정책을 적용합니다.
- 작성·수정 중복 제출을 제어하고 실패 시 사용자가 입력 내용을 복구할 수 있게 합니다. 삭제는 합의된 확인 흐름을 적용합니다.
- 입력에 레이블을 연결하고 키보드 조작과 지정된 화면 크기에서 필수 기능을 확인합니다.
- 모의 데이터로 확인한 동작과 실제 서버 연결로 확인한 동작을 나누어 보고합니다.

### QA 담당
- 요구사항·계약에서 시험 항목을 도출하고 기대 결과를 구현 관찰 전에 정합니다.
- 범위에 포함된 CRUD·검색·페이지 처리의 정상 흐름과 잘못된 입력, 없는 ID, 중복 제출, 권한 거부를 점검합니다. XSS·SQL 주입 방어 확인은 승인된 로컬 테스트 환경에서 수행합니다.
- 테스트 데이터와 환경, 대상 커밋 또는 파일 상태, 실행 절차, 기대·실제 결과와 재현 근거를 기록합니다.
- 결함 보고는 최소 재현 단계, 영향, 발생 조건을 포함합니다. 수정 후 해당 재현 시험과 영향받는 회귀 시험을 다시 실행합니다.
- QA 산출물은 시험 코드와 결과·결함 기록으로 제한합니다. 별도 수정 작업을 배정받지 않은 제품 코드는 변경하지 않습니다.

### 인계
- 변경한 파일과 완료 조건별 검증 결과를 전달합니다. 검사가 실패하면 수정으로 생긴 실패와 환경·기존 실패를 근거로 구분합니다.
- 실행 불가 항목은 실패 또는 미실행 상태와 필요한 환경을 보고합니다. QA가 확인하지 못한 기능을 통합 검증 완료로 표현하지 않습니다.

## Must NOT
- 미배정 영역, 다른 담당자의 변경 또는 공유 계약을 임의 수정하지 않습니다.
- 시험 통과를 위해 권한 검사나 입력 검증을 제거하지 않습니다.
- 실데이터나 운영 DB를 테스트 픽스처로 사용하지 않습니다.
- QA가 발견한 결함을 숨기거나 기대 결과를 실제 동작에 맞춰 바꾸지 않습니다.

## Definition of Done
- 배정된 범위의 산출물과 재현 가능한 검증 근거가 준비됩니다.
- 계약 차이, 실패와 미실행 항목이 인계 내용에서 구분됩니다.
- 다른 담당자가 연결·재시험하는 데 필요한 조건과 알려진 제한을 확인할 수 있습니다.
