# AI 직원 시스템 메뉴·화면 설계

- 상태: 구현 전 화면 설계안. 프로토타입의 표시는 샘플이며 실제 API의 성공을 뜻하지 않는다.
- 기준 문서: [한국어 요구사항 정의서](../request/ai-employee-system-requirements.ko.md). 참고 화면: [프로토타입](../prototype/index.html), [안내서](../prototype/guidebook.html).
- 추가 개정: 2026-10-14. FR-19/20의 메뉴는 M-15/M-16으로 추가하며 기존 메뉴 ID는 유지한다. 운영 API 연결은 별도 구현 대상이다.
- 실행 계약: [전체 설계](./system-architecture.md), [동작 설계](./action-design.md). `M-xx`는 메뉴, `A-xx`는 설계상 동작 ID다. 프로토타입의 `data-action`과 동일하게 취급하지 않는다.

## 1. 탐색과 공통 표시

| 구분 | 표시 순서 |
|---|---|
| 주 메뉴 | 대시보드 → AI 직원 → 조직·직원 → 업무 지시 → Task 이력 → 업무 일지 → 세션 대화 → 1:1 면담 |
| 운영 메뉴 | 관리 AI 일정 → 복구 센터 → MCP 사용 지표 → AI 정책 → 스킬 등록 → 페르소나 템플릿 → 환경 설정 → 가이드북 |

공통 화면에는 자체 CSS 토큰으로 만든 사이드바·상단 바·경로 표시·표·상태 배지·알림·검색을 사용하고 Bootstrap을 불러오지 않는다. 한국어 UI, 파비콘, 키보드 조작, 대화상자 포커스 관리, 표 머리글, 색상에만 의존하지 않는 상태 표시가 필요하다. 좁은 화면에서는 사이드바와 표를 각각 접거나 가로로 스크롤할 수 있어야 하며 입력란이 겹치면 안 된다. 대시보드 상단은 현재 프로토타입 구성을 기준으로 하고, 제외된 요소를 근거 없이 되살리지 않는다.

| 공통 상태 | 화면 규칙 |
|---|---|
| 불러오는 중 | 표·상세·대화상자마다 뼈대 화면 또는 로딩 표시를 제공하고 중복 제출을 막는다 |
| 비어 있음 | 미등록·권한 없음·검색 조건 불일치를 구분하고 다음에 가능한 작업을 보여 준다 |
| 부분 데이터 | 대화 수집 누락, 작업 근거 부족, 비용 불명을 `0`이나 완료로 바꾸지 않는다 |
| 충돌 | `expected_revision` 충돌을 표시하고 최신값을 다시 가져온 뒤 재확인하게 한다 |
| 시간 초과 | 결과 불명으로 표시하고 같은 요청 키로 Operation을 조회하게 한다. 무조건 새 요청을 보내지 않는다 |
| 저장하지 않고 이탈 | AI 직원 생성·수정 등 변경된 양식에는 편집 계속·이동 후 폐기 중 선택하게 한다 |
| 권한 | 화면뿐 아니라 API에서도 권한 없는 작업을 거부한다. 직접 URL을 입력해도 권한 없는 상세를 읽을 수 없다 |

이름과 값은 모두 안전하게 이스케이프하고 로그·Markdown·산출물에 포함된 명령을 UI 설정으로 해석하지 않는다. 감사 ID는 상세 화면으로 연결할 수 있지만 인증 정보는 표시하지 않는다.

## 2. 주 메뉴

### M-01 대시보드

| 항목 | 설계 |
|---|---|
| 목적 | 직원, 실행 중 작업, 검토 대기, 재개 대기, 승인 대기, 다음 관리 AI 실행과 대응 필요 항목을 한 화면에서 확인 |
| 표시 | 집계 카드, 최근 감사 이벤트, 진행 중인 유한 작업, 계속 업무 실행 회차. WorkProcess에는 전체 진척도를 표시하지 않는다 |
| 데이터 | 권한을 확인한 집계 조회 모델과 Task·WorkCycle·WakeEvent·Approval·Run. 갱신 시각을 명시 |
| 작업 | 카드에서 해당 목록으로 이동, 알림 상세, 직원·작업 전체 검색. 검색은 읽기 권한이 있는 대상만 반환(A-30, A-32) |
| 빈 상태·이상 | 데이터 없음·수집 지연·DB 일시 장애를 구분한다. 오래된 집계에는 수집 시각과 구식 데이터 표시를 붙인다 |

대시보드에는 업무 지시 입력 양식을 중복으로 두지 않는다. 새 요청은 M-04로 안내한다.

### M-02 AI 직원

| 항목 | 설계 |
|---|---|
| 목적 | AI 직원과 첫 세션을 함께 만들고 현재·과거 세션 설정 및 대화 진입점을 제공 |
| 목록 | 직원, 담당 업무, 종류, 소속/미배정, 세션 표시 이름, 현재/이력, 모델, 기본 페르소나, 기본 스킬, 실제 ID/미발급, 작업 열과 직원 필터 |
| 새 양식 | 이름, 담당 업무, 관리/작업 종류, 선택적 세션 표시 이름, 모델, 페르소나 템플릿과 편집란, 복수 스킬, 작업 위치, 설정 미리보기를 한 화면에 배치(A-01) |
| 공통 정책 | 개별 스킬 선택과 AI 정책의 읽기 전용 공통 스킬을 분리한다. 미리보기와 현재 세션 표에는 공통/개별 출처·정책 revision·중복 제거된 집합을 표시한다. 과거 정책 미기록은 최신 정책으로 채우지 않는다(M-16, A-35) |
| 기존 세션 | 직원을 명시해 세션 추가(A-02). 현재 세션 설정은 다음 실행 경계부터 적용(A-03). 과거 세션은 읽기 전용 |
| 이동 | 세션 대화·스킬 등록·페르소나 템플릿으로 이동. 변경된 양식이 있으면 먼저 이탈 경고 |
| 이상 | CLI 미실행·초기화 중·실제 ID 미확보·실패·사용할 수 없는 모델을 구분하고 표시 이름을 실제 Codex ID로 오인하지 않게 한다 |

생성 직후에는 조직 미배정, 호출 불허 상태다. 세션 표시 이름을 비우면 앱이 기본 이름을 붙인다. 실제 세션 ID는 CLI에서 확인할 때까지 ‘미발급’으로 표시하며 이름으로 추측하지 않는다.

### M-03 조직·직원

| 항목 | 설계 |
|---|---|
| 목적 | 조직·소속·직속 관계·인사이동·관리 AI의 호출 허가를 관리한다. 모델·스킬·페르소나 설정 화면으로 쓰지 않는다 |
| 조직 목록 | 조직 이름, 관리 AI 수, 작업 AI 수, 직원 수, 조직도 링크. 오른쪽 위에 ‘조직 생성’(A-04) |
| 조직도 | 행 선택 시 대화상자 열기. 연결선은 직속 관계만 뜻한다. 직원 카드에서 소속·직속·호출 권한 상세로 이동 |
| 직원 배치 | ‘AI 직원 추가’를 누르면 조직도를 남겨 둔 채 같은 대화상자 아래쪽에 패널을 펼친다. 현재 세션이 있는 미배정 AI 선택기와 작업 AI의 선택적 직속 관리 AI를 표시(A-05) |
| 권한·이동 | 관리 AI 상세에서 호출 허용 대상을 명시적으로 선택(A-07). 직속 변경(A-06)·인사이동(A-08)·보관(A-09)은 이력과 권한 폐기를 확인 |
| 검증 | 조직 중복·순환 관계·중복 배정을 거부한다. 배치할 때 이름과 담당 업무를 다시 입력시키지 않는다. 필수 `*`는 라벨 옆에 두고 선택기 높이를 맞춘다 |

직속 관리 AI에 호출 권한이 자동으로 생기지는 않는다. 허용 집합의 기본값은 비어 있으며 다른 조직의 작업 AI도 운영자가 명시적으로 허용한 경우에만 후보가 된다. 인사이동·직속 변경 시 이전 권한을 폐기하고 새 관리 AI에게 자동 부여하지 않는다. 현재 프로토타입의 조직 상세에 남은 이름·담당 업무 편집란은 실제 구현에서 M-02로 모을 예정인 알려진 차이다.

### M-04 업무 지시

| 항목 | 설계 |
|---|---|
| 목적 | 사용자가 관리 AI에게 보내는 WorkOrder를 만들고 접수 상태·관련 작업·결과 보고서를 확인 |
| 목록 | ‘지시 목록’과 ‘결과 보고서’ 탭. 제목, 관리 AI, 생성 시각, 상태, 관련 작업 수, 보고 여부 표시 |
| 생성 | 제목, 현재 세션이 있는 관리 AI, 요청 내용, 결과 보고에서 확인할 사항을 입력(A-10). 작업 AI와 작업을 직접 지정하지 않는다 |
| 상세 | 지시 본문, 확인 항목, 관련 Task·WorkProcess, 결과 보고서와 근거, 상태·감사 기록. 보류·재개는 A-11 |
| 이상 | 접수와 실행을 구분한다. 저장 즉시 작업·업무 일지·보고서가 자동 생성됐다고 표시하지 않는다. 결과 불명은 A-30으로 조회 |

관리 AI의 보고서 제출은 MCP의 A-16이다. 사용자 화면에서 AI의 보고 본문을 가장해 작성하지 않는다.

### M-05 Task 이력

| 항목 | 설계 |
|---|---|
| 목적 | AI가 생성·실행한 유한 작업과 끝이 없는 계속 업무의 실적을 읽기 전용으로 확인 |
| 유한 작업 목록 | 상태 필터, 이름·ID·담당자 검색, 담당자, 관련 WorkOrder, 근거가 확인된 완료 조건 수, 진척도, 최근 실행 |
| 작업 상세 | 조건 이름·양수 가중치·확인 근거·버전, 결과, Checkpoint, 본인의 WorkLog, 모든 실행, 관련 WorkOrder 링크 |
| 계속 업무 | WorkProcess 목록과 상세. 기한이 도래한 회차의 `done`·`missed`·사유 있는 일시 중지, 다음 일정, 파생된 미해결 작업 표시 |
| 진척도 | 유한 작업은 근거가 확인된 조건의 가중치 비율. 기준 없는 기존 작업은 ‘기준 미설정’. 계속 업무에는 전체 백분율을 표시하지 않는다 |
| 작업 경계 | 사용자용 작업 생성·일지 편집 양식을 두지 않는다. 정정은 운영자 전용 감사 기록을 수반하는 A-31로 수행 |

파생 작업이 늘어도 WorkCycle의 실행 회차 분모는 바뀌지 않는다. 백분율 100만으로 완료 처리하지 않고 산출물과 최종 확인을 별도로 표시한다.

### M-06 업무 일지

| 항목 | 설계 |
|---|---|
| 목적 | 같은 AI가 다음 실행에서 작업을 이어가기 위해 중간에 남긴 WorkLog를 사용자가 읽음 |
| 목록 | 기록 ID, 작성 AI, 관련 Task·WorkProcess, 요약, 기록 시각. AI와 작업 선택기로 필터링 |
| 상세 대화상자 | 작업 요약, 이번에 완료한 사항, 확인 근거, 미완료 항목과 다음 행동, 실행, 참조 버전, 관련 작업 링크를 전문으로 표시 |
| 작업 | 읽기·필터링만 허용. AI 본인의 추가 기록은 System MCP A-14. 다른 AI용 수락 버튼은 두지 않는다 |
| 이상 | 관련 작업이 없어도 ID와 누락 표시를 남긴다. 근거 누락이나 오래된 버전을 명시하고 완료 처리하지 않는다 |

다른 AI의 WorkLog를 권한 있는 사용자가 참고로 읽을 수 있더라도 재개 대상 AI에 대한 암묵적 지시로 사용하지 않는다.

### M-07 세션 대화

| 항목 | 설계 |
|---|---|
| 목적 | AI 직원별 현재·과거 세션에서 수집 가능한 대화를 모든 페이지에 걸쳐 확인 |
| 탐색 | 세션 전환, 직원 이름, 표시 이름, 모델, 현재/이력, 실제 ID, 수집 범위를 표시. 과거 세션은 읽기 전용 |
| 본문 | 사용자 발언, 공개 AI 응답, 공개 도구 입출력, 오류, 시각, 실행 ID, 출처를 시간순으로 표시. 도구 내용은 펼칠 수 있게 한다 |
| 수집 | 커서 페이지 이동, 검색, SSE 추가 및 재연결. `complete_for_source`·`partial`·`unsupported`·`missing`을 명시(A-28, A-30, A-32) |
| 작업 경계 | 프로토타입의 채팅 전송은 데모 응답일 뿐이다. 실제 업무 지시는 M-04, 상담은 M-08에서 시작하며 이 화면에서 작업을 직접 실행하지 않는다 |
| 이상 | 로그 누락·미지원 형식·가려진 부분의 위치와 이유를 표시한다. 저장되지 않은 대화나 비공개 추론을 만들어 채우지 않는다 |

### M-08 1:1 면담

| 항목 | 설계 |
|---|---|
| 목적 | 사용자가 관리 AI 또는 작업 AI와 개별 상담하고 합의 사항과 후속 작업을 추적 |
| 목록·본문 | AI 선택, 의제, 전용 Interview·Session, 면담 대화, 합의 사항, 공유 가능한 요약, 과거 이력 |
| 작업 | 면담 시작·계속(A-22). 합의한 후속 작업을 사용자가 명시적으로 선택해 관리 AI 대상 WorkOrder로 복사(A-23) |
| 제어 | 일반 업무 쓰기 도구는 기본적으로 비활성화. 면담 발언을 무단으로 작업·운영 지시·상사에게 공유하는 전문으로 전환하지 않는다 |
| 이상 | 대상 AI에 면담 세션이 없으면 전용 세션 준비 상태를 표시. 인사이동 후에도 면담 이력 읽기 권한을 다시 평가 |

## 3. 운영 메뉴

### M-09 관리 AI 일정

| 항목 | 설계 |
|---|---|
| 목적 | 관리 AI별 cron·시간대·기본 프롬프트·스킬·실행 이력·수동 실행을 관리 |
| 표시 | 활성/중지, 식, 다음 예정, 최근 WakeEvent, 기본 프롬프트, 참조하는 `skill_set_version` |
| 작업 | 5필드 cron 구문과 다음 시각 미리보기를 검증한 뒤 저장·활성화(A-18). 수동 실행은 별도 WakeEvent(A-19) |
| 제어 | 동일 `schedule_id + scheduled_at`의 중복을 거부. 같은 세션이 실행 중이면 대기시키거나 합쳐서 중복 실행을 막는다 |
| 이상 | 파서 미지원·잘못된 시간대·예산 부족·재개 대기·권한 폐기를 실행 결과에서 구분 |

cron 실행 신호와 WorkProcess의 수행 기록은 별개다. 수동 실행만으로 WorkCycle을 `done`으로 바꾸지 않는다.

### M-10 복구 센터

| 항목 | 설계 |
|---|---|
| 목적 | 강제 종료·MCP 시간 초과·실행 상태 불명을 분류하고 안전한 재개·중지를 판단 |
| 표시 | 종료 원인 근거, 관련 Task·Operation·Run, `next_eligible_at`, 남은 시도, 이전 프로세스 생존 여부, Checkpoint, WorkLog, 외부 부작용 대조 결과 |
| 작업 | 허용된 일시 종료의 자동 재개 예약(A-20), 명시적 중지(A-21), 불명확한 부작용의 승인·보류(A-29), Operation 조회(A-30) |
| 제어 | 60초는 최소 대기 시간이다. Retry-After나 사내 정책이 더 길면 연장한다. 사내 허용 여부가 확인되지 않은 자동 재개는 비활성화 |
| 이상 | 인증 만료·금지·원인 불명·이전 프로세스 생존·시도 한도·외부 부작용 불명은 재개 버튼을 비활성화하고 근거를 표시 |

프로토타입의 ‘60초 경과’는 가상 시계 표시이므로 실제 시스템에는 해당 조작을 두지 않는다.

### M-11 스킬 등록

| 항목 | 설계 |

| 목적 | AI 직원이 선택할 수 있는 스킬을 운영 메뉴에서 등록하고 버전 관리 |

저장 형식은 `---`, `name`, `description`, `---`, 본문 순이다. AI 직원 양식에서 이동하기 전에 변경 사항 폐기 경고를 표시한다.

## 5. 프로토타입을 실제 구현으로 옮길 때의 차이

| 현재 프로토타입 | 실제 구현 시 처리 |
|---|---|
| `localStorage`에 직원·조직·지시·일지 저장 | DB·인증·감사 기록으로 교체. 브라우저 표시 성공을 업무 성공으로 간주하지 않는다 |
| 조직 상세에 남은 이름·담당 업무 편집란 | M-02의 AI 직원 설정으로 모은다. M-03은 소속·직속·호출 권한으로 한정 |
| 세션 대화의 샘플 전송 | 업무 지시는 M-04, 상담은 M-08. M-07은 기본적으로 로그를 읽는 화면 |
| 복구 센터의 가상 60초와 샘플 재개 | DB의 `next_eligible_at`와 사내 허용 조건으로 대체. UI 버튼으로 대기 시간을 줄이지 않는다 |
| 데모 데이터 초기화 | 운영 데이터의 물리 삭제 기능으로 옮기지 않는다. 보존·삭제에는 별도 요구사항과 승인이 필요 |
| 브라우저 안의 모델 요금·스킬 등록 | 수동 요금 버전 관리와 `SKILL.md` 검증으로 대체. 실제 청구액이나 스킬의 CLI 적용 여부는 PoC에서 확인 |
| 고정 샘플 MCP 지표 | 인증된 호출 관측 이벤트와 수집 범위를 집계. 운영 상태·Task 완료를 샘플 성공으로 판정하지 않음 |
| 브라우저 공통 AI 정책 | DB의 버전 정책과 Runner 스킬 스냅샷으로 교체. 사용자 CODEX_HOME의 전역 스킬을 임의 수정하지 않음 |
