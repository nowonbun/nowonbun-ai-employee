# AI 직원 시스템 요구사항 정의서 — 한국어판

- 원본: 2026-10-06 작성, 2026-10-08 개정, 문서 버전 0.3. 이 판은 한국어 환경의 요구사항 검토용이다.
- 대상: 웹, 시스템 MCP, Scheduler, Runner, DB, Codex 대화 로그 연동.
- **요청 요구사항**은 이용자 필수 조건, **추가 제안**은 채택 여부 결정이 필요한 항목, **설계안**은 구현 후보, **미검증**은 실기기 확인 대상이다.
- 원문 문서가 작성될 당시에는 구현 완료를 뜻하지 않았다. 이 한국어판도 현재 기능의 완성을 증명하지 않는다.
- 한국어판 지역화 기준: 화면·안내 문구는 한국어, 기본 시간대는 `Asia/Seoul`, 날짜·숫자는 `ko-KR`로 한다. API 식별자, DB 키, 상태 코드, 파일 형식 리터럴은 호환성을 위해 유지한다. 원문의 일본어 UI 및 `Asia/Tokyo` 지정은 한국어판에서 대체한다.
- 관련 문서: [한국어 기획서](./ai-employee-system-plan.ko.md), [프로토타입](../prototype/index.html), [한국어 가이드북](../prototype/guidebook.html). 실제 프로그램 구현 여부는 별도 검증해야 한다.

## 1. 목적·문제·성공 기준

AI 직원을 초기 세션과 함께 생성한 다음 조직에 배치한다. 사람의 업무 지시부터 결과 보고까지, 각 AI의 Task·업무 일지·대화를 관련 ID로 추적한다. Codex 대화는 세션으로 이어가되 업무 상태와 재개 메모의 정본은 DB다. 관리 AI는 cron에 따라 시작하고 허용된 실무 AI의 업무를 비동기 위임·추적한다.

- 대상: 관리·실무 AI를 조직화해 조사·개발·검토를 지속하려는 엔지니어와 운영자.
- 문제: 문맥 압축 후 상태 오인, 장시간 동기 대기, 종료 후 재개 누락, 이동·위임에 따른 책임 불명확, 종료 시점 없는 업무에 근거 없는 진행률 표시.
- 이용자가 제시한 사내 강제 종료 상황은 운영 조건으로만 다룬다. 종료 신호와 재개 허용 조건은 미검증이며 사내 제한을 우회하지 않는다.
- 성공: WorkOrder, 예약 시작, MCP 위임, AI 결과·업무 일지, 관리 AI 보고서를 연결해 추적한다. 통신 단절에도 접수된 Task가 사라지지 않고 재전송으로 증식하지 않는다.
- 허용된 일시 종료에서는 60초 이상 기다리고 DB 체크포인트를 확인해 미완료분만 계속한다. DB 보존만으로 환각의 완전 방지나 timeout의 완전 제거를 보장하지 않는다.
- 유한 Task의 진행률은 근거가 있는 완료 조건으로만 계산한다. 무기한 WorkProcess에는 전체 진행률을 붙이지 않는다.
- 초기 범위는 로컬·단일 운영자·여러 부서/직원이다. 웹·MCP·Scheduler·Runner 코드는 TypeScript로 작성한다. 다중 이용자는 추가 제안이다.

## 2. 용어와 통제 경계

| 용어 | 의미 |
|---|---|
| `Employee` | 불변 `employee_id`를 가진 관리/실무 AI 직원 |
| `Session` | 직원의 대화 단위. 표시명·앱 ID·CLI의 실제 ID는 별개 |
| `WorkOrder` | 사람이 관리 AI에 맡기는 업무 지시와 결과 확인 항목 |
| `WorkProcess` | 종료 시점 없는 지속 업무. 예정 실행 회차와 파생 Task 보유 |
| `Task` | 완료 조건이 있는 유한 업무. 여러 Run 가능 |
| `Run` | CLI를 한 번 시작한 실행 시도. 종료해도 Task/Session은 유지 |
| `Operation` | Web/MCP 비동기 요청의 접수·진행·조회 단위 |
| `WorkLog` | 같은 AI가 업무 재개를 위해 남기는 자기 업무 일지. 다른 AI의 인계 수신 기록이 아님 |
| `TaskAssignmentEvent` | 위임·담당 변경·적용 시각에 대한 감사 이벤트 |
| `Checkpoint` | 확인된 작업 상태와 다음 안전한 시작 위치 |
| `ContextSnapshot` | Run이 참고한 Task·일지·결정·설정 버전 |
| `WakeEvent` | cron·수동·결과 알림·재개 예약 등의 시작 이유 |
| `Interview` | 업무 세션과 분리된 사람-직원 1:1 면담 |

사람은 조직·권한·모델·스킬·일정·가격을 설정하고 업무를 지시·확인하며 위험 작업을 승인한다. 관리 AI는 계획·허용된 위임·검토·통합을, 실무 AI는 배정 업무·자기 일지·검증 근거를 담당한다. 애플리케이션 서비스는 ID·인가·상태·중복·배타성·감사를 결정론적으로 처리한다. Scheduler/Runner는 시작 조건·프로세스·재개를 관리한다. LLM의 문장으로 실행 권한을 부여하지 않는다.

실행 모드는 예약 실행, 사전 허용 범위의 자동 실행, 범위가 고정된 사람 승인, 운영자 전용 작업으로 나뉜다. 외부 전송·공유 상태 변경·새 쓰기 범위·운영 환경 작업은 사람 승인이 필요하다. 권한·정책·인증·물리 삭제는 AI용 도구로 공개하지 않는다. 종료 이유나 부작용이 불명확하면 사람의 판단을 기다린다.

## 3. 요청 항목과 선행 기획 변경

초기 요청 12건은 FR-01~FR-12, 후속 프로토타입에서 정한 6건은 FR-13~FR-18이다. 한국어판에서는 원문의 ‘일본어 UI’를 ‘한국어 UI’로, 기본 시간대 `Asia/Tokyo`를 `Asia/Seoul`로 변경한다. 다음 설계 변경은 그대로 유지한다.

- TypeScript를 필수 언어로 확정한다.
- 모델 변경은 실행 중 프로세스 hot-swap이 아닌 **다음 Run 경계**에서 적용한다.
- 실패 후 원칙적 수동 재시도에 더해 **허용된 일시 제한에만** 60초 뒤 자동 재개를 요구한다.
- 통신 기한·프로세스 생존 감시·업무 예산을 분리하고 고정 30분 제한을 필수로 보지 않는다.
- 관리 AI에 cron 시작과 영속 inbox/outbox의 결과 알림을 추가한다.
- 스킬 집합의 버전과 Run별 적용 기록을 둔다.
- 직원 생성과 첫 Session 준비는 하나의 화면 흐름으로 묶고 조직 배치는 분리한다.
- 조직 배치·직속 관계와 호출 권한은 별개이며 기본 호출 권한은 거부다.
- 유한 Task와 지속 업무의 진행 기준을 분리한다.

## 4. 기능 요구사항

### FR-01 관리 AI의 cron 시작과 기본 업무

- 관리 AI별 cron 식, 시간대, 활성 상태, 기본 프롬프트, 스킬 집합을 설정한다. 한국어판 기본 시간대는 `Asia/Seoul`이다.
- 초기 제안은 초 없는 5필드 cron이다. 저장 전에 문법과 다음 시작 시각을 미리 보여준다.
- Scheduler는 DB에 발화를 기록하고 직원 상태·권한·예산·잠금을 검사한 뒤 Run을 만든다. `schedule_id + scheduled_at`은 유일하다.
- 같은 세션을 중복 시작하지 않는다. 중단 기간의 모든 발화를 연달아 실행하지 않고 최신 점검 최대 한 건만 합친다. 개별 업무 요청은 합치며 잃지 않는다.
- 기본 프롬프트는 DB 상태, 미처리 결과, 계획·위임, 상태 갱신, 근거가 있는 보고를 포함한다. 할 일이 없으면 idle을 기록하고 끝낸다.
- 웹에서 비활성화·수동 시작·다음 예정·마지막 결과를 다룬다. 인수: AT-01, AT-13.

### FR-02 직원 생성 시 스킬 집합

- 관리·실무 AI 생성에서 여러 스킬을 페르소나와 별도로 고른다. 카탈로그는 ID·이름·설명·출처·버전/hash·필요 도구·허용 상태를 가진다.
- 직원 설정과 Run에 `skill_set_version`을 남긴다. 설치와 직원별 활성화는 구분하며 허용되지 않은 소스는 자동 취득·실행하지 않는다.
- 스킬 문서 선택은 권한 부여가 아니다. 미허용 도구는 시작 전에 알리고 중단 또는 제외한다. 실행 중 버전은 불변이고 변경은 다음 Run부터 적용하며 철회 이력을 남긴다.
- CLI 어댑터에서 실제 적용 여부를 검증한다. 사용자 전체 스킬을 임의 변경하지 않는다. 인수: AT-02.

### FR-03 DB 정본 Task·업무 일지·이력

- AI가 실제 시작한 업무를 Task 또는 WorkProcess 회차에 연결하고 시작 이유, 지시, 담당, Run, 상태, 도구 결과, 산출물, 검증을 DB에서 추적한다. 사람의 WorkOrder는 AI 처리 전에도 독립적으로 존재할 수 있다.
- 1:1 대화는 Interview로 구분하고 사람이 채택한 합의만 WorkOrder로 넘긴다. 실행하지 않은 시작은 WakeEvent에 남긴다.
- WorkLog에는 기록자, 관련 Task/회차·Run·시각, 요약, 완료 항목, 근거, 미완료, 다음 행동, 참조 revision을 담는다. 자기 재개용 추기 기록이며 다른 AI의 수신 상태가 아니다.
- 일지는 실행 중에도 주기적으로 추가할 수 있다. 사람 화면은 목록·필터·전문 팝업을 **읽기 전용**으로 제공한다. 담당 변경은 WorkLog가 아니라 `TaskAssignmentEvent`로 기록한다.
- 문맥 압축·재개·모델 변경 후 Task, 최신 자기 일지, Checkpoint, 담당 변경, 결정, 미처리 이벤트를 DB에서 다시 읽는다. Run별 ContextSnapshot과 출처·범위를 보존한다.
- 파괴 작업·완료 판정 전 최신 revision을 대조하고 오래된 변경을 거부한다. AI가 ‘완료’라고 말한 것만으로 Task를 완료하지 않는다.
- DB 기록이 불가능하면 새 시작·위임·쓰기를 멈춘다. 정정은 감사 추기 이벤트로 남긴다. 인수: AT-03, AT-04, AT-17.

### FR-04 Codex 로그의 세션별 대화

- `log_source_roots`를 설정·진단하고 직원 → Session → 실제 CLI 세션 ID에 따라 대화를 보여준다. 읽기 루트 변경과 실행용 `CODEX_HOME` 변경은 별개다.
- 직원 세션 목록은 직원·표시명·모델·용도·상태·실제 ID를 그리드로 보여주며 현재/과거를 구별한다.
- 허용된 기존 세션 연결·첫 Session 등록·재색인을 제공하고 한 실제 세션을 여러 직원에 임의 공유하지 않는다.
- 발언·공개 도구 입출력·오류·시각·Run 연결의 모든 페이지를 볼 수 있다. 새 실행 JSONL과 기존 로그의 출처, parser 지원 범위·누락·마스킹을 구분한다.
- 작성 중 행·회전·손상·중복을 처리하되 같은 본문의 정당한 반복 발언을 지우지 않는다. 원본과 인증 파일은 편집·공개하지 않는다. 저장되지 않은 대화·내부 추론은 복원해 ‘전체’라고 부르지 않는다. 인수: AT-05, AT-18.

### FR-05 TypeScript 구현

웹·API·MCP·Scheduler·Runner·도메인을 TypeScript로 작성한다. `strict`를 켜고 외부 입력·DB·CLI 이벤트·LLM 출력은 런타임 schema로 확인한다. TypeScript 형만으로 실행 안전을 보장한다고 보지 않으며 미지 이벤트는 마스킹해 격리한다. DB·웹 프레임워크·cron/MCP 라이브러리는 선택 사항이다. 인수: AT-06.

### FR-06 비동기 자식 프로세스·장시간 실행

- Node.js `child_process.spawn()`을 기본안으로 하며 장시간 작업에 `spawnSync()`·`execSync()`를 쓰지 않는다. CLI 프로세스 종료와 Session/Task 삭제는 별개다.
- Web/MCP는 DB에 영속 접수 후 Operation·Task·Run ID를 곧바로 반환한다. 브라우저나 HTTP/MCP 연결이 닫혀도 업무는 유지한다.
- Runner는 HTTP 요청 수명과 분리되고 stdout/stderr·JSONL·진단·backpressure·출력 상한을 처리한다. 검증된 cwd, 파일/인자 배열, 제어된 stdin을 사용하고 셸 확장을 피한다.
- 시작 오류·종료 코드·signal·`close`·취소를 구별하고 종료 처리에 멱등성을 둔다. 고아 프로세스를 감지한다.
- 통신 timeout, heartbeat, 진행 정체, 업무 예산을 분리한다. PID나 detached만으로 복구를 보장하지 않고 DB lease·생존 확인을 사용한다. 인수: AT-07, AT-13.

### FR-07 강제 종료 후 1분 대기·재개

- 사내 정책상 재시도가 허용된 일시 제한으로 **확인된 경우에만** Task를 미완료 `cooldown`으로 두고 60초 이상 대기한다. 종료 signal 또는 무출력만으로 토큰 제한이라고 단정하지 않는다.
- `next_eligible_at = max(terminated_at + 60초, retry_after_at, policy_not_before)`를 DB에 저장한다. 상대 `Retry-After`는 절대 시각으로 변환한다. 예약은 재시작 후에도 남는다.
- 대기 중 cron·MCP·수동 시작으로 제한을 우회하지 않는다. 이전 프로세스 종료, lease, 최신 Task·권한·Checkpoint·부작용을 대조한 다음 **새 Run**에서 같은 업무의 미완료분만 재개한다.
- 실제 세션 ID가 유효해야 한다. ID 불명·재개 불가이면 멈추고 새 세션과 확인된 문맥 이관을 사람에게 묻는다.
- 자동 재개 횟수·전체 기간에 한도를 둔다(초기안 3회). 제한이 계정·조직 단위라면 해당 범위에서 cooldown을 공유한다. 사내 허용 조건을 확인하기 전까지 자동 재개는 비활성화한다. 인수: AT-08, AT-09, AT-13.

### FR-08 조직 구성·인사 이동

- 부서·관리/실무 AI·직속·역할·유효 기간을 구성하고 순환을 거부한다. 조직 화면은 소속·직속·호출 권한에 한정하며 직원 이름·업무·모델·페르소나·스킬 편집은 ‘AI 직원’ 화면으로 모은다.
- 조직 목록은 직원 수를 표로 보이고 행 선택 시 조직도 대화상자를 연다. 조직도를 유지한 채 배치 패널을 펼쳐 기존 미배치 AI의 현재 Session을 선택한다. 이름·업무를 다시 입력하지 않는다.
- 한 직원의 이중 배치를 UI와 DB에서 막는다. 이동은 직원 ID를 유지하며 이전/이후 조직·상사·역할·이유·행위자·적용 시각을 남긴다.
- 직속 관계와 명시적 `CallPermission`은 별도다. 기본 호출은 거부이며, 허용된 유효 실무 AI만 호출 가능하다.
- 실행 중 이동은 안전한 Run 경계에 적용하되 긴급 권한 철회는 즉시 중단한다. 미완료 Task는 본인 유지·다른 직원 이관·보류를 사람이 고른다.
- 이전 호출 권한을 폐기하고 새 상사에 자동 부여하지 않는다. 토큰·예약·승인·알림과 과거 대화·면담 열람 권한도 재평가한다. 보관 후에도 업무 이력 연결을 유지한다. 인수: AT-10, AT-30.

### FR-09 관리/실무 AI와 1:1

- 사람은 어느 유형의 AI와도 별도 Interview ID·전용 Session에서 대화한다. 의제·발언·합의·숙제·시각·모델을 보관한다.
- 상담 세션의 업무 쓰기 도구는 기본 비활성이다. 발언을 자동 업무로 바꾸지 않는다. 사람이 명시적으로 채택한 숙제만 관리 AI 앞으로 WorkOrder를 만든다.
- 다른 직원에게 전문을 자동 공유하지 않는다. 공유 요약은 명시적으로 선택한다. 이동 후에도 같은 직원 ID로 이력을 추적한다. AI 간 자동 면담은 추가 제안이다. 인수: AT-11.

### FR-10 모델 설정·업무 중 변경

- 직원별 기본 모델을 두고 요청 모델 `gpt-6.1-sol`을 후보로 유지하되 이용 가능 여부는 별도 확인한다. 실행 중 hot-swap은 가정하지 않고 다음 Run 경계에서 바꾼다.
- Run마다 요청 모델·확인 가능한 실제 모델·설정 버전·변경 이유·행위자를 남긴다. 확인 불가한 실제 모델은 ‘알 수 없음’으로 표시한다.
- 먼저 동일 세션의 명시적 resume와 모델 인자 조합을 실제 검증한다. 지원되지 않으면 사람 동의 후 새 Session에 DB ContextSnapshot을 넘기고 연관 이력을 남긴다.
- 즉시 변경은 안전 중단·부작용 대조 후 새 Run을 만든다. 대기열 Run을 몰래 변경하지 않으며 모델 불가 시 자동 대체하지 않는다. 인수: AT-12.

### FR-11 시스템 MCP 위임·timeout 복구

- 관리 AI의 실무 AI 호출은 시스템 MCP만 통한다. 다른 직원 CLI를 직접 시작하지 않는다.
- 쓰기 도구에는 `idempotency_key`가 필수다. 영속 접수 후 `operation_id`, Task ID, 담당 이벤트 ID를 반환한다. 같은 호출자·작업·키·본문은 기존 Operation을, 다른 본문은 conflict를 반환한다.
- 도구는 업무 완료까지 기다리지 않는다. timeout 뒤 같은 키로 접수 여부부터 조회한다. MCP 재연결 시 인증·권한을 다시 확인하고 영속 cursor에서 미처리 이벤트를 읽는다.
- 결과·outbox를 같은 트랜잭션에 저장하고 inbox에 최소 한 번 배달한다. `event_id`로 중복 제거한다. 관리 AI가 종료·대기 중이어도 결과를 보존하고 DB 반영 뒤 ACK한다.
- 통신 재접속·요청 기한·재전송 한도는 설정 가능하되 통신 복구와 업무 재실행은 별개다. 인수: AT-14~AT-16.

### FR-12 관리 UI, Bootstrap 사용 금지

- SB Admin 2의 시각 방향만 참고해 사이드바·상단 바·집계 카드·표·상태 배지를 제공한다. 코드를 가져오거나 라이선스 미확인 소재를 전용하지 않는다.
- 주요 순서: 대시보드 → AI 직원 → 조직·직원 → 업무 지시 → Task 이력 → 업무 일지 → 세션 대화 → 1:1 면담. 운영 메뉴: 관리 AI 일정 → 복구 센터 → 스킬 등록 → 페르소나 템플릿 → 환경 설정 → 가이드북.
- 한국어판의 목록·양식·대화상자는 한국어로 표시하고 favicon을 둔다. Bootstrap CSS/JS·CDN·종속 컴포넌트·Bootstrap 전제 템플릿 복사를 금지한다.
- 색·간격·글꼴·모서리·그림자를 토큰화한다. 상태는 색뿐 아니라 문자·아이콘으로 구별한다. 좁은 화면의 사이드바, 키보드·포커스·표 머리글·대비를 지원한다. 인수: AT-19.

### FR-13 직원·첫 세션의 통합 생성

- 하나의 화면 흐름에서 이름·담당 업무·관리/실무 유형·선택적 Session 표시명·모델·페르소나·기본 스킬을 정한다. 조직 배치는 나중이며 미배치를 허용한다.
- 실제 비동기 처리에서는 Employee·첫 Session·초기 Operation의 연관 ID를 보존하고 실패 시 미준비·재시도 상태를 보인다. 실제 CLI ID를 표시명으로 추정하지 않는다.
- 직원당 현재 Session은 하나, 과거 Session은 목록으로 유지한다. 직원 편집의 미저장 입력을 버리고 다른 화면으로 이동할 때 ‘계속 편집 / 이동하고 폐기’를 선택하게 한다. 인수: AT-23.

### FR-14 사람의 업무 지시와 AI 기록 분리

- 사람이 직접 작성하는 업무 진입점은 WorkOrder이며 제목·담당 관리 AI·의뢰 내용·보고서 확인 항목을 받는다. Task 분해와 실무 AI 지정은 관리 AI·업무 서비스 책임이다.
- WorkOrder는 접수·실행·보류·보고·확인 필요 상태와 Interview 출처, 관련 Task/Process, 보고서·근거·행위자·시각을 기록한다.
- Task 이력·업무 일지는 AI/서비스의 기록을 사람이 읽는 화면이며 직접 생성·수정 폼은 없다. 정정은 별도 감사 절차다.
- 일지는 기록 AI·관련 Task로 거르고 전문 팝업에 요약·이번 완료·근거·미완료·다음 행동·시각을 보인다. WorkOrder 저장과 AI 시작은 서로 다른 상태 전이다. 인수: AT-24.

### FR-15 유한 Task와 지속 업무의 진행 기준

- 유한 Task의 완료 조건에는 버전·양의 가중치·검증 방법을 둔다. AI 자기 선언만으로 확인 완료로 표시하지 않는다.
- 진행률은 `100 × Σ(근거가 있어 확인된 조건의 가중치) / Σ(유효 조건의 가중치)`다. Task 수·하위 Task 수·Run 수·시간·과거 임의 값으로 분모를 만들지 않는다. 100%만으로 업무 완료가 되는 것은 아니다.
- 조건 변경은 이유·행위자·버전·적용 시각과 이전 값을 보존한다. 조건 없는 옛 Task는 ‘기준 미설정’으로 표시한다.
- 종료 시점 없는 WorkProcess는 전체 백분율 없이 cadence·시간대·다음 예정·기한 도래 회차·실시/미실시·미해결 파생 Task를 표시한다. 회차 분모는 기간 내 예정 횟수로 고정한다. 인수: AT-25, AT-26.

### FR-16 스킬 등록·페르소나 템플릿

- 스킬 직접 생성은 `name`, `description`, 본문을 받고 UTF-8 `SKILL.md`를 미리 보여준다. 업로드는 frontmatter의 두 필드와 본문을 검사하며 별도 스킬 ID·표시명 입력을 요구하지 않는다.
- 내부 ID·버전·hash는 시스템이 관리한다. 잘못된 형식·중복 이름·빈 본문·잘못된 UTF-8·크기 초과를 거부한다. 문서 안의 명령으로 권한을 올리지 않는다.
- 공통 페르소나 템플릿을 생성·버전 관리하고 직원 설정으로 선택·복사한다. 템플릿 갱신으로 실행 중 Session을 몰래 바꾸지 않는다. 인수: AT-27.

### FR-17 모델별 가격 수동 설정

- 입력·캐시 입력(선택)·출력 단가를 모델별 `USD / 100만 토큰`으로 수동 등록한다. 공란(미설정)과 `0`(명시적 무료)은 다르다.
- 모델명·통화·단위·적용 시각·버전·수정자를 저장하고 음수·비수치를 거부한다. 단가 입력은 공식 가격 자동 수집이나 실제 청구액이 아니다. 사용량이 있으면 별도 **추정** 비용으로 표시한다. 인수: AT-28.

### FR-18 가이드북

운영 메뉴 마지막에 한국어 HTML 가이드북을 두고 직원 생성·조직 배치·호출 권한·업무 지시·Task/일지·진행 기준·스킬/페르소나·모델 가격·복구를 설명한다. 실제 화면·제품 버전과 일치시킨다. 데모·미연결 기능을 구현 완료로 설명하지 않는다. 인수: AT-29.

## 5. 비동기 실행·복구 설계안

Web·MCP·Scheduler는 공통 Application Service와 DB를 거쳐 영속 Run 대기열에 접수한다. Runner가 `spawn()`으로 CLI를 시작하고 이벤트·결과를 DB에 기록해 Web SSE/inbox로 전달한다. 시스템 MCP(직원·위임)와 외부 시스템 MCP(직원의 외부 작업)는 인증·연결을 분리한다.

공통 단계는 입력 수집 → 의도 해석 → DB 문맥 조회 → 계획 → 도구 실행 → 결과 검증 → 응답 → 기록·관측이다. 각 단계는 ID·출처·revision을 남기고 모호함·권한 부족·증거 부족·상태 불명 시 멈추거나 사람에게 확인한다. 감사와 Checkpoint는 마지막뿐 아니라 수행 중에도 기록한다.

| 대상 | 초기 설계안 | 이상 처리 |
|---|---|---|
| Web/MCP 접수 | p95 2초, 요청 기한 10초 | 동일 키로 결과 조회 |
| MCP 재연결 | 1·2·5·10·30초 | 5회 후 접속 대기·운영자 알림 |
| SSE | heartbeat 15초·cursor 보존 | DB에서 미수신 이벤트 재조회 |
| Runner lease | heartbeat 10초·기한 45초 | 생존·소유권·부작용 대조 후 판단 |
| CLI 무출력 | 일률적 종료 조건 아님 | 프로세스와 진행을 별도 진단 |
| Run 업무 예산 | 관리자 지정 유한 한도 | 안전 중단, 무승인 초기화 금지 |
| 이용 제한 대기 | 최소 60초·서버/사내 조건 우선 | FR-07 적용, MCP 재연결과 구별 |

- Operation: `accepted → queued → running → succeeded / failed / cancelled / blocked`.
- WorkOrder: `queued → accepted → running → reported / paused / needs_attention / cancelled`.
- WorkProcess 회차: `scheduled → due → done / missed / skipped_with_reason`.
- Task: `draft → ready → queued → running → reviewing → completed`, 중간에 `awaiting_approval`, `waiting_assignment`, `cooldown`, `needs_attention`, `cancelled`.
- Run: `queued → starting → running → succeeded / failed / terminated / cancelled / unknown`, 취소 중 `cancelling`.
- 재개는 이전 Run을 끝난 채 보존하고 `resume_of_run_id`와 시도 번호를 가진 새 Run으로 만든다. 같은 Session의 실행은 항상 하나다. DB lease·fencing token을 사용하되 외부 부작용까지 fence 가능하다고 가정하지 않는다.

MCP 응답만 잃었으면 Operation을 조회하고 새 업무를 만들지 않는다. 허용된 일시 제한은 60초 이상 대기 후 상태를 확인한다. 인증 만료·금지·원인 불명·부작용 불명·사람 취소는 자동 재실행을 금지한다. DB/Runner 복구에서는 살아 있는 프로세스와 미배송 outbox를 대조한다. 부분 외부 쓰기는 결과를 확인하고 필요 시 사람 승인 아래 보상 작업을 한다. 취소·재개·DB 복원을 자동 롤백과 혼동하지 않는다.

## 6. DB·이력·문맥

DB는 WorkOrder·WorkProcess·Task·WorkLog·담당 변경·설정의 정본이다. 대화 원본은 허용된 로그 소스에 있고 검색 인덱스·요약·표시 캐시는 파생 데이터다. 실제 세션 식별에는 호스트/home 문맥도 포함한다. 업무 상태·버전·마스킹한 공개 대화·감사·산출물 참조를 영속화하고 대형 산출물 본체는 보호 저장소에 둔다. 버퍼·불완전 출력·단기 인증은 유일한 기록처로 사용하지 않는다.

오래된 상태는 revision·설정 버전·원본 세대·만료 시각으로 찾아낸다. 권한 변경 시 캐시뿐 아니라 예약·승인·토큰도 무효화한다. ContextSnapshot은 필요한 것만 전달하고 전체 대화를 매번 투입하지 않는다. 같은 AI가 재개할 때 자기 최신 일지와 Task 정본을 대조하며 타 AI의 일지를 암묵적 지시로 쓰지 않는다. 외부 작업의 intent와 결과를 모두 기록하고 intent만 있으면 상태 불명으로 조회한다. 배송은 at-least-once를 기본으로 하며 논리적 중복은 DB 제약과 멱등 처리로 막는다. 외부 부작용의 무조건 exactly-once는 보장하지 않는다.

| `task_checkpoint` | task_id·revision·확인 작업·다음 단계·근거·멱등 키 | 확인된 사실 추기 |
| `work_log_append` | Task/Process 회차·요약·완료·근거·남은 일·revision·멱등 키 | 인증된 본인의 일지만 추기 |
| `work_cycle_record` | WorkProcess·예정 시각·결과·근거·파생 Task·멱등 키 | 회차 결과를 유일하게 기록 |
| `task_result_submit` | Task·revision·결과·근거·멱등 키 | 결과·outbox 저장, 곧바로 완료 아님 |
| `work_order_report_submit` | WorkOrder·revision·보고서·근거·멱등 키 | 사람 확인 대기 |
| `operation_get` | operation_id 또는 request_key | 접수·실행 상태 |
| `inbox_read` / `inbox_ack` | cursor·limit / event_id·반영 revision·멱등 키 | 미처리 결과 수신 / 영속 반영 후 ACK |
| `run_cancel` | run_id·사유·멱등 키 | 중단 요청, 결과는 별도 조회 |

입력 schema와 호출자·직원·부모 Task·위임 범위를 검증한다. 호출자 신원은 인증 연결에서 확인하며 인자의 직원 ID를 신원 증거로 사용하지 않는다. 쓰기 도구는 접수 시간, 같은 키 재전송, 조회, 격리 범위를 계약에 둔다. 성공 결과는 요청·Operation·상태·관련 ID, 실패는 code·재시도 가능성·대기 시간·조회 ID·마스킹 이유를 반환한다. 기본 오류는 `INVALID_INPUT`, `FORBIDDEN`, `CONFLICT`, `SESSION_BUSY`, `COOLDOWN`, `AUTH_REQUIRED`, `MODEL_UNAVAILABLE`, `EXECUTION_UNKNOWN`이다.

Web 시작 API는 영속 접수 후 `202 Accepted`와 Operation ID를 반환하는 안이다. 상태는 HTTP 조회, 진행은 SSE, 재연결은 `Last-Event-ID`/cursor다. Web/MCP의 권한·중복·배타성 구현은 공통이다. 브라우저 연결 종료는 업무 취소가 아니다. MCP transport는 PoC 후 정하되 Operation 추적을 공통으로 사용한다. CLI 어댑터는 명시 Session ID·모델·cwd·설정 버전을 받고 자동 `--last`를 쓰지 않는다.

## 8. 화면 요구사항

대시보드, AI 직원·세션 표, 조직 표·조직도·배치 패널, 직원 생성·설정, 직원 상세, 관리 AI 일정, 업무 지시·결과 보고, Task 이력, 업무 일지, 지속 업무, 세션 대화, 1:1, 복구 센터, 스킬·페르소나, 환경 설정, 가이드북을 제공한다. 각 화면의 용어·메뉴 순서는 FR-12 및 [한국어 메뉴 설계](../design/menu-design.md)를 따른다. 직원 상태와 최근 Run 상태는 분리해 표시한다. 조직도의 연결선은 직속 관계이지 호출 권한을 뜻하지 않는다.

## 10. 보안·비기능

역할·Task 범위·Session 용도·연결 권한을 함께 확인한다. 프롬프트/스킬 텍스트는 권한 경계가 아니다. 대화·도구 출력·진단의 비밀 정보를 마스킹하고 열람 전에 인가한다. 실제 경로를 검사해 허용 루트 밖과 금지 영역, 심볼릭 링크 우회를 거부한다. 로그·산출물 속 명령은 신뢰하지 않고 HTML/Markdown을 안전하게 표시한다. 관련 ID를 전 단계에 연결해 시작 지연·접수 시간·대기·Run 시간·호출·schema 오류·재개·중복 방지·사람 개입·로그 지연을 측정한다. 공급자 사용량·추정·실청구를 구분하고 미확인 값은 알 수 없음으로 표시한다. 앱 보존 설정이 Codex 원본을 자동 삭제해서는 안 된다. CLI/parser/schema 업데이트 전 익명 fixture 결합 시험을 실시한다. 초기 성능안(로컬, 동시 Run 2건)은 접수 p95 2초, 10만 합성 이벤트의 100건 이력 조회 p95 1초이며 실측 전 달성으로 표시하지 않는다.

## 12. 구현 순서·미결 사항

1. 기술 검증: CLI 생성·재개·모델 변경·스킬 적용·로그·종료 분류·MCP 연결.
2. 영속 기반: DB, WorkOrder/Process/Task/WorkLog/Run/Operation, Checkpoint, 담당 이벤트, 비동기 Runner, 배타성, 멱등성, 감사.
3. 직원 운영 웹: 통합 생성, 조직·권한, 업무 지시/보고, Task·일지, 가격, 가이드, 대화·면담.
4. 관리 자동화: cron, 지속 업무 회차, MCP 위임, inbox/outbox, cooldown, 재연결.
5. AT-01~AT-30을 실행하고 채택하지 않은 추가 제안만 별도 범위로 둔다.

미결: 강제 종료 신호와 사내 재개 허용 조건, 제한의 적용 단위, 자동 재개 상한(초기안 3회), cron 기본 빈도, DB 제품, Web/CSS 방식, CLI 스킬 적용, 동일 세션 모델 변경, MCP transport, AI 간 면담, WorkOrder/Task 경계, 완료 조건 변경 권한, 지속 업무 집계 기간, 공식 가격 자동 수집 여부, PR-01~08 채택 여부. 해당 결정을 내리기 전 특히 사내 정책이 불명확한 자동 재개를 활성화하지 않는다.

## 13. 검증 범위

이 문서의 FR-01~18 및 AT-01~30 대응, 한국어 용어, UTF-8·참조 검사는 **문서 검증**이다. CLI 실행, timeout 복구, 사내 정책 준수, UI 완성을 증명하지 않는다. 원본의 ‘당시 문서만 변경했다’는 기록은 원본 작성 범위에 관한 역사적 설명이지 현재 한국어판 작업의 변경 범위가 아니다.
